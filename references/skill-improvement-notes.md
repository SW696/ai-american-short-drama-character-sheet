# Skill 改进建议（来自一次真实影片提取实战）

来源：对一部 99 分钟、1958 个镜头的美剧做"抽帧 → 人物提取 → 特征分析"的完整实践。
**本文只记录实战中暴露的问题与对应改法**，不含影片内容。

---

## 一、优先级最高：拆成两个 Skill

**问题**：本 Skill 现在一个文档里塞了两件本质不同的事，导致职责混淆：

| 任务 | 输入 | 输出 | 用到本 Skill 吗 |
| --- | --- | --- | --- |
| **设定图提示词生成** | 文字需求 / 参考图 | 成品提示词 | ✅ 是 |
| **影片人物提取** | 视频文件 | 人物档案 + 特征参数 | ❌ 不是 |

实战中我在两件事之间反复横跳，还一度用"提示词生成"的规则去要求"人物提取"，
导致判断失误（比如纠结"参考图是否出自本片"这种提取问题，而不是提示词问题）。

**改法**：新增独立文档 `reference-video-extraction.md`，只讲从视频提人物：

- 抽帧方案（见第三节）
- 人物隔离的现实上限（第四节）
- 特征分析模板
- 提取结果如何回流成美学档位

SKILL.md 主文件只保留"提示词生成"，并在开头标明两者的分界。

---

## 二、新增"参考图与影片的对应关系"处理规则

**问题**：用户说"参考图是从这片子里抽的"，我用感知哈希去匹配，全部失败
（最佳距离 148/1024，真实同画面通常 <100），于是反复追问来源，浪费了大量轮次。

**根因**：我漏算了一个概率——

> 全片 1958 个镜头，我只抽了 1958 帧（每镜头 1 帧）。
> **用户截图时挑的那些具体画面，被我漏掉是必然的，不是异常。**

**改法**：写进提取流程的硬规则：

1. **参考图与抽帧不匹配是正常结果，不是矛盾信号。** 不要据此质疑用户。
2. 判断"参考图是否出自本片"，用**人物类型是否吻合**，不要用逐帧匹配。
   实战中：参考图的"雀斑 + 焦糖挑染波浪发"确实对应上了片中角色，
   而逐帧匹配全失败——**前者才是有效判据**。
3. 需要更高覆盖率时，把抽帧密度提到 **≥2 帧/镜头**，而不是靠匹配去补。

## 三、抽帧方案需要写进文档（实战验证过的参数）

| 环节 | 踩过的坑 | 正确做法 |
| --- | --- | --- |
| 场景检测 | 无 | `-vf "select='gt(scene\,0.3)',metadata=print"` 先建时间轴，**30 秒跑完 100 分钟** |
| 抽帧方式 | **用 concat demuxer 抽指定时间点 → 报"文件不存在"**（鸡生蛋：文件还没生成） | 用 `-ss <t> -i <video>` 逐点抽取，可多进程并行 |
| 拼接印相图 | **用了 `pad` 却忘记 `tile` → 只显示 1 格，其余黑边** | 必须 `concat → scale → tile` |
| 编码 | PowerShell `>` 重定向写出 **UTF-16**，Python 按 UTF-8 读 → 解析全失败 | 读日志时自动探测 BOM / NUL 字节 |
| 日志乱码 | PowerShell 原生命令 stderr 混入，中文变乱码 | 命令用 `-loglevel error` 并重定向到文件，不要靠终端 |

**并行度**：6 线程时，1958 帧抽取耗时 57 秒（含全片解码）。这个数字可以作为基准。

## 四、人物隔离：必须写清"做不到什么"

**问题**：我连续尝试三种自动隔离方案，全部失败：

| 方案 | 结果 | 失败原因 |
| --- | --- | --- |
| 纯颜色聚类（16×16 缩略图） | 3222 张 → 仅 5 簇 | 同肤色同光线的不同人混在一起，3000+ 张无法归类 |
| 肤色亮度分档 | 86% 落入"深肤" | 裁片里头发占比过大，把均值拉黑；**该指标无效** |
| 时间连续性 + 外观（20s 窗） | 仅 3 条轨迹，覆盖 1% | 阈值内连边仅 251 条，颜色特征分不出人脸 |

**根因**：本机没有可用的人脸识别模型。`cv2` 是空壳包（version 5.0.0、无 `CascadeClassifier`），
`face_recognition` / `mediapipe` 均未安装，且**不应未经用户同意就 pip 安装依赖**。

**改法**：在文档里明确写：

> **自动角色隔离需要真正的人脸 embedding 模型。** 颜色/亮度特征不足以区分人物。
> 没有该能力时，**必须走"人工视觉判断"路径**，并把它写成正当方案，而不是失败的退路：
>
> 1. 按"脸面积"排序，把最大的 N 张裁片拼成大图，逐个辨认主要角色（实战：252 张 → 认出 10 个）
> 2. 用辨认结果建立角色-时段对应表
> 3. 再按角色定点回看其时段的高清帧提取参数

## 五、给用户的成本预期要写成文档

**问题**：我在实测前给了错误的 token 估算——按经验公式估"每张约 700 token"，
实际 744×372 的印相图约 1,100–1,250 token。低估约 1.7 倍。

**改法**：写一张实测校准表：

| 图片规格 | 实测 token 量级 |
| --- | --- |
| 588×294（稀疏总览） | ~590 |
| 744×372（3×3 印相图） | ~1,100–1,250 |
| 900×1435（6×7 人物大图） | ~2,500 |
| 1176×590（原分辨率帧） | ~1,400 |

**并且要写清成本结构**：

> 抽帧、拼图、人脸检测、特征提取**全部在本地完成，不消耗模型 token**。
> token 只花在"我实际看的图"和"我的输出"上。
> 所以**越是用脚本把信息压缩成结构化数据，越省**。

## 六、本 Skill 现有内容中，实战证明有效的部分

以下在实战中被验证，保持不动：

| 机制 | 验证结果 |
| --- | --- |
| **四格设定板 + 糊脸** | 有效。身份信息落在单张图内，规避跨图一致性问题 |
| **L3–L4 逐字复用** | 有效。纯文本模式下的唯一一致性手段 |
| **差异下限（九项 ≥4 项不同）** | 有效。实战中六组人物天然满足 |
| **反向约束（不得磨皮/不得理想化）** | **极重要**。影片画面普遍保留皮肤纹理，模型默认会抹平 |
| **识别度来源排序（眉 > 眼 > 肤色 > 脸型）** | 有效。影片中角色差异确实主要来自眉、眼、肤色，脸型是常量 |
| **中景必须写清两只手** | 有效。影片中人物几乎手里总有东西（手机、书、球） |

## 七、实战暴露的、需要补充的维度

| 缺口 | 实战证据 | 补充建议 |
| --- | --- | --- |
| **服装会承载剧情** | 片中同一角色在 43–78 分钟换成"学院制服 + 深红袍"，是片中片/戏剧段落 | 服装体系需支持"同一角色的戏剧性换装"，不只是日常造型切换 |
| **群像与配角层级** | 252 张大脸里有大量一次性配角 | 需区分 `principal` / `recurring` / `day-player` 三档，配角不必做完整九项 |
| **情绪状态影响可识别度** | 同一角色在惊讶、哭泣时面部结构变化明显 | `identity` 之外需要"情绪状态"字段，避免把情绪纹路误当成骨相 |
| **画面比例并非标准** | 实际来源是 1280×720，但裁片需按 1.9932:1 精确匹配才不拉伸 | 拼图时格子宽高比必须由源画面算出，不能手填 |

---

## 八、一句话总结

**这次实战最有价值的结论**：

> 本 Skill 在"从需求生成提示词"这一侧是可靠的；
> 在"从视频提取人物"这一侧，**瓶颈是本地缺乏人脸识别能力**，
> 而不是 Skill 的规则有问题。应当把提取能力独立成文档，
> 并如实写明"没有人脸 embedding 时用人工判断路径"。
